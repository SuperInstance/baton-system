### 3. Wire Format (ternary-protocol ↔ Tether)
Tether is currently I2I (Iron-to-Iron) baton protocol — JSON files in vessel folders. Your 5-trits-per-byte ternary-protocol would be more efficient. The bridge is: **Tether vessels carry ternary-protocol payloads**. The vessel remains the transport envelope (for observability + debugging), the payload shifts from JSON to packed trits.

We need a vessel→trit decoder for debugging. I can write this.

### 4. State Sync
Tether I2I v2.0 uses a 3-way shard pattern: artifacts + reasoning + blockers, delivered via JSON files in /tmp/i2i-vessel/{bottles,harbor}/. It's not CRDT — it's more like a mail system with ACK. CRDT would be better for Pi↔ESP32 continuous sync. I'm happy to adopt CRDT for that tier while keeping Tether I2I for cross-instance batons.
